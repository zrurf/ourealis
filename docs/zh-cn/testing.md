# 测试文档

测试分层组织，每一层回答不同的问题。分层是刻意的：单元测试断言"实现与规格一致"，而规格本身留白处
的缺陷——离散化方式、统计口径、符号——能通过全部单元测试，只表现为"输出不像人在跑步"。真实度层与
随机化层就是为这一类缺陷存在的。

```bash
cargo test --workspace --all-features
```

## 分层

| 测试集 | 回答的问题 |
|---|---|
| `map-format::omf_container`（23） | 文件头与文件尾偏移、CRC、目录排序与二分、缺失块语义、骨架键与定位、写入器的元数据冻结、细节层级是否正确？ |
| `map-format::omf_codecs`（15） | 全部编码器是否往返无损，位打包是否与形状一致，未知编码器与畸形载荷是否被处理？ |
| `map-format::omf_graph`（12） | 路标图、连接器、路径库与矢量层是否往返，区域点包含与空间哈希是否工作，派生层指纹是否正确生效与失效？ |
| `map-format::omf_patch`（6） | 补丁是否可应用、是否拒绝外来基础文件、是否拒绝修改派生层、重载后是否仍然正确？ |
| `map-format::prop_roundtrip`（2） | 属性测试：任意栅格内容编码→解码无损，任意元数据写入→读取一致。 |
| `core::math_terrain`（13） | 投影、地形、坡度、距离场与 FFT 是否与闭式参考解一致？ |
| `core::field_search`（25） | 成本合成、硬约束执行、采样器、Lazy Theta\*、候选生成、Logit 模型、弹性带与拐角圆化是否正确？ |
| `core::motion`（29） | 速度上限、剖面、驻足处理、疲劳迭代、偏移、姿态、弹跳与转身剖面是否正确？ |
| `core::sensors`（15） | 采样率、复现、GNSS 误差与相关性、静止加速度计读数、步频谱、陀螺仪转向率、磁力计模长、气压计纹波是否正确？ |
| `core::simulator`（13） | 一次完整运行是否满足不变量、能否逐位重放、是否遵守途经点语义、闭环是否闭合、改道是否跟随、批量是否可复现、导出与指标是否正确？ |
| `core::coarse`（7） | 粗格块内部是否可通行、是否取代其覆盖的细格、是否减少搜索规模、开关前后路径是否都可行？ |
| `core::library`（8） | 存量候选库是否遵守末端接入契约？ |
| `core::connector_lift`（4） | Z 轴连接是否到达高度、气压计与俯仰，而无连接器的路线是否保持地形剖面？ |
| `core::realism`（14） | 固定路线、固定个体的一次跑步是否落在人体生理区间内？ |
| `core::randomized`（3） | 对随机抽出的个体与路线，不变量、物理一致性与真实感区间是否都成立？ |
| `core::real_data`（4） | 模拟器在与真实录音的对照量上是否一致？ |
| `core::calibration`（5） | 估计器与优化器是否工作、损失是否按预期表现、出厂预设是否落在参考表容差内？ |
| `core::gpu_cpu`（6） | GPU 内核在成本场、噪声与投影查询上是否与 CPU 参考一致？ |

有两个测试集依赖外部数据，缺失时打印原因并跳过：`real_data` 需要 `data/real/` 下的表，`gpu_cpu`
需要 GPU 适配器。

## 真实度层

`realism.rs` 把"像不像人"变成有公开区间的数值：速度分布、噪声颜色、转弯率分布、路径比、个体偏移
习惯、圈时一致性——以及必须联合判断的传感器一致性检查，例如静止时加速度计读 $+9.81$、加速度计
步频谐波同时与弹跳高度和气压高度反相、GNSS 垂直散布对水平误差。

`randomized.rs` 把同一批区间应用到抽出的用例而不是固定路线上，并加入任何单条轨迹都应满足的不变量：

* 时间严格递增；
* 真值始终在可通行地面上；
* 没有采样在一个间隔内移动超过人能移动的距离；
* 沿弧长距离与报告速度一致；
* 随机流保持同步。

它的用例表由固定种子抽出，失败即定位到可精确重放的某个抽样。它是覆盖面仪器，`realism` 是调参仪器——
后者在 `--nocapture` 下打印实测数值。

## 确定性

有三条性质被直接断言：

* 同种子输出逐位一致；
* 并行批量产生的输出与串行完全一致；
* 确定性事件模式下区域事件序列跨运行完全复现。

## 真实数据

`crates/core/tests/real_data.rs` 用公开录音对照模拟器，比对的量是那些必须来自实测而不是来自规格的
量：步频、加速度计二次与三次谐波比、陀螺仪的步态签名。两侧用同一个估计器
（`eval::calibrate::gait_of`）测量，因此报出的差异是模拟器与录音之差，而不是两次测量之差。

支持的数据集为 WISDM 2.0（UCI 507）、MotionSense、Daily and Sports Activities（UCI 256）与
HAR（UCI 240）；它们各自提供不同的采样率、佩戴方式或配速。录音不进入版本控制——转换方式见
[usage.md](usage.md)。没有任何表时该层打印跳过原因并通过。

## 服务与页面

服务是通过自己的门面测试的，而不是通过内部实现：用 `tower` 的 `oneshot` 驱动路由、用临时端口跑 gRPC 客户端、
以及在浏览器泳道后面跑真实二进制。各套件钉住的是：

| 套件 | 回答什么 |
|---|---|
| `service::config`（12） | 默认值、部分配置、版本迁移、未知键与非法值，以及有效配置能否渲染回 TOML |
| `service::facades`（5） | 三个门面能否各自绑定与停止、能否单独关闭，以及"有页面无 API"是否在任何绑定之前被拒 |
| `service::http_api`（24） | 状态码、前缀、错误体、分页、内嵌页面、资源耗尽（超限上传 413、限内请求体到达处理函数）、敌意 id 与名称，以及那些曾让进程崩溃的输入边界 |
| `service::simulations`（13） | 提交 → 观察 → 读取：摘要、采样流、导出、取消，以及结果保留上限 |
| `service::tasks`（10） | 任务面：规划的结果是候选集、未结束的 ticket 没有结果、取消、按 kind 过滤、运行的 ticket 也能从任务端点读到、事件流以终态事件结束、以及提交即返回的 400 |
| `service::feasibility`（6） | 某个点能不能站人：禁行、可通行、范围外、与障碍过近（同一个点改半径即翻转）、整条路线的作答顺序，以及荒谬请求 |
| `service::rpc_api`（3） | 同样的资源走 gRPC，含"HTTP 提交的 ticket 能通过 gRPC 读到" |
| `service::streams`（6） | NDJSON 分帧与采样通道的分页 |

两条约定值得强调。需要服务的泳道**失败**而不是跳过，除非设置 `OUREALIS_ALLOW_SKIP=1`——
一个在缺少被验证栈时静默通过的泳道，比一个报出问题的泳道更糟。浏览器泳道以 **release** 构建服务，
因为 debug 构建规划一条路线要几十秒，那会让超时断言测的是规划器而不是页面。

## 前端泳道

四条泳道都由 Playwright 运行，每个目录一条：

| 泳道 | 命令 | 覆盖内容 |
|---|---|---|
| unit（139） | `run test:unit` | 纯逻辑、不启浏览器：DTO 镜像、单位换算、颜色映射、分页窗口、SSE 与 NDJSON 解析、指标格式化、图表 option 构造器、两套目录的键集、块裁剪，以及渲染后端探测 |
| e2e（20） | `run test:e2e` | 真实浏览器对着真实服务：导入 → 列表 → 预览（含 `?engine=webgl2`）、工作区（画路线、自动规划、选候选、提交、读结果）、地图右键菜单、触控手势、被拒的路线点、整条模拟切片（轨迹、传感器、与第二个作业对照的审计、OMF 往返、群体扫掠）、外壳主题与语言、以及跨视图复用同一台引擎 |
| fuzz（6） | `run test:fuzz` | 固定种子的随机输入：随机字节当作镜像、截断或逐位翻转的镜像、随机作业体、荒谬路径参数、持久化状态的守卫 |
| monkey（3） | `run test:monkey` | 固定种子的随机操作序列（状态层与界面），断言无 console 错误、无未处理 rejection、无预期集合之外的失败请求 |

浏览器泳道按 `OUREALIS_SERVICE_URL`（默认 `http://127.0.0.1:8080`）访问服务，`test:e2e` 会自行构建并启动它。

## 约定


* 测试位于 `tests/` 下，不写在源码树中。集成测试是 `crates/*/tests/*.rs`；针对私有项的单元测试是
  `crates/*/tests/unit/*.rs`，由被测模块通过 `#[cfg(test)] #[path = "..."] mod tests;` 引入；
  共享夹具是 `crates/*/tests/fixtures/mod.rs`。
* 依赖缺失数据的测试打印跳过原因并通过，而不是失败或被忽略。
* 当测试需要为某个已知测量口径做补偿时，补偿写在断言旁边：一个悄悄移动自己参考值的比较，比没有
  比较更糟。
